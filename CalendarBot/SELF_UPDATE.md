# Обновление через Telegram

Администратор вызывает `/update` и подтверждает действие. Бот:

1. Обновляет API/веб через существующий SSH forced command или локальный
   `UPDATE_SCRIPT` и проверку доступности сервера.
2. Если основной сервер обновился успешно, проверяет отсутствие локальных
   изменений в отслеживаемых файлах собственного репозитория.
3. Выполняет `git pull --ff-only` в каталоге своего кода, ставит
   `requirements-bot.txt` тем же Python, которым запущен бот.
4. Проверяет компиляцию кода и создание приложения без запуска polling.
5. Запрашивает `systemctl --user --no-block restart` для `BOT_UNIT`
   (по умолчанию `calendar-bot`). XDG/DBus указывают на текущего пользователя.

Все операции выполняет пользователь службы; sudo и пароль в Telegram не нужны.
Он должен владеть рабочей копией/venv, иметь доступ к Git remote и своему
пользовательскому systemd. Если этап не прошёл, рестарт не запрашивается.
Повторный `/update` повторяет установку зависимостей даже если Git уже обновлён.
В одном процессе параллельные обновления отклоняются.

Первоначальная установка этого механизма требует одного внешнего обновления
кода и перезапуска: старая версия сама этот код установить не умеет.
Установка нового кода не гарантирует автоматический откат на предыдущий коммит;
rollback пока не реализован. Если сам основной API не прошёл проверку,
обновление бота также останавливается.
